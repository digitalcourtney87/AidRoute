# Domain QA — aidroute.org (2026-08-15)

Follow-up to [04-production-qa-2026-08-15.md](04-production-qa-2026-08-15.md),
run after `aidroute.org` was added as the custom domain.

## Verdict

The domain works completely: apex 308s to canonical `https://www.aidroute.org`,
HTTP upgrades to HTTPS with HSTS, all four pages render with zero console
errors (desktop + mobile), and the app is domain-agnostic by construction
(relative fetches only, no CORS/origin checks, no hardcoded self-URLs).

The Supabase store — down in the 04 report — is now verified healthy on the
live deployment, both reads (live `/brief` render) and writes (an
`{"extracted": []}` merge probe exercises the full versioned
`replace_claims` cycle without changing content).

## ISSUE-006 materialized: the Claude integration is down

04's ISSUE-006 warned the Anthropic call had never been exercised because the
store failed first. With the store fixed, that second failure is now visible:
typed `/api/ask` questions, `/api/checklist`, and real-debrief `/api/extract`
all 422 in under a second — too fast for a model call, and with the routes'
non-store fallback copy (so `isStoreFailure()` correctly says the store is
fine). Identical on `aid-route-five.vercel.app`, so it is not domain-related.

Ruled out: model ID `claude-sonnet-4-6` is a valid, active Anthropic model and
`temperature: 0` is accepted on it. Root cause is the deployment env:
**`ANTHROPIC_API_KEY` missing or invalid in Vercel.**

**Operator action:** set a valid `ANTHROPIC_API_KEY` (paste once, single line —
same pitfall as the Supabase key outage) in Vercel Production env, redeploy,
then verify with a typed question on `/ask`. Runtime logs distinguish the two
cases: `ANTHROPIC_API_KEY is not set` vs `Claude API 401`.

## Code remediation in this branch

- ISSUE-002: `lib/store-errors.ts` now classifies Claude failures
  (`isClaudeFailure`) and returns honest copy (`AI_UNAVAILABLE_MESSAGE`)
  instead of the "check the connection / rephrase" fallbacks — the AI-side
  twin of 04's ISSUE-005 store-copy fix. `callClaude` wraps transport-level
  failures (DNS, TLS, connection reset) so they classify too, and the
  classifier is anchored to the message start so model-echoed text can't
  spoof it. Regression test: `tests/store-errors.regression-1.test.ts`.
